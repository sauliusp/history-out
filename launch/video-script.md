# HistoryOut v2: 50-second product video

Prepared 5 September 2026 and reconciled with the v2.0.0 release-candidate controls. Target: a 50-second 1920 × 1080 demonstration, readable without audio, using the all-new brand identity and actual v2 UI. This is the script and recording brief, not a finished or published video.

## The single story

“I saw a useful page yesterday. I want to resume that research and keep the relevant links.” Show the daily benefit first, then a useful file. Browser-neutral narration. The recording can use a verified Chrome build without claiming that other browsers were tested.

Allow natural pauses. The narration is approximately 80 words, leaving room for the screen to explain the actions. Saved views are implemented. Show the required Preview action after restoring one; do not imply that selecting a view automatically loads history. Recap totals describe the loaded range, while the ready count describes filtered export rows.

## Recording setup

- Use a dedicated test profile and a synthetic, internally consistent public research dataset. Keep personal history, client information and signed-in account pages out of the recording.
- Pick one named example project, such as “Reading list,” with 12-20 relevant pages mixed among harmless unrelated sites. The visible result should change when a filter is applied.
- Use a real testable v2 build and record the browser/version/OS in the QA handoff. If the UI is a fixture rather than a real extension session, label the deliverable a UI preview and do not treat it as end-to-end verification.
- Record 1080p with a readable UI scale, a deliberate cursor, clean microphone audio and no music that competes with speech. Keep output rows large enough to read.
- Capture a real exported file and open it. Do not substitute a designed spreadsheet for actual output.
- Use the new icon, type/color system and freshly composed end card. No existing image assets and no introductory logo animation.
- Export an MP4, a separate caption file and a new 1280 × 720 thumbnail. Keep an editable project or reproducible source for later UI updates.

## Delivery status and publication boundary

A completed deliverable consists of the actual MP4, caption file, thumbnail, and a verification note confirming that the recorded UI and downloaded file match the release build. A storyboard, still-image montage or placeholder animation is not a completed product demonstration. Uploading to YouTube and changing the live store listing are separate external publication steps.

The Chrome Web Store accepts a YouTube link showcasing the extension. [Official listing documentation](https://developer.chrome.com/docs/webstore/cws-dashboard-listing).
