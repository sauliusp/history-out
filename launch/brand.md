# HistoryOut v2 brand

Prepared 5 September 2026 for the v2.0.0 release candidate. The identity is newly created for this release. Preserve the HistoryOut name and existing store item; replace the old icon, website imagery, promotional graphics and screenshots.

## The central idea

**Find your way back.**

HistoryOut helps people return to a useful page, resume a project and keep the links that matter. Browser history becomes something they can use during the day, with precise export available whenever they need a file.

The daily benefit leads. CSV, JSON and HTML are evidence of usefulness and a strong search acquisition channel. We are building a personal history companion with useful outputs. We are not claiming to measure attention, productivity, billable time or a complete workday.

## Icon rationale

The new source mark is [logo.svg](./assets/source/logo.svg). It uses a dark rounded square, three short white list lines, a clear arrow pointing outward, and a small blue baseline detail. The list represents a useful browsing record. The outward arrow connects that record to reopening a page and taking useful links out into a file. The compact geometry avoids a generic browser logo and remains recognizable beside other extension icons.

The mark is functional: list, action, output. Do not describe it as a lock, a tracking radar, an AI spark, a Chrome logo or a guarantee of security. Its meaning supports both daily revisiting and the existing export utility.

Render crisp PNG variants from the new vector source at the actual extension sizes. Inspect 16, 32, 48 and 128 pixels at native size. Keep the arrow and list distinct when small; adjust a dedicated small-size variant if needed rather than adding detail. Use the icon without stretched proportions, photographic mockups, extra shadows or an old identity mixed into the new one.

Use light blue as an accent, not small body text on white. Confirm contrast and legibility in actual layouts. The brand palette is authoritative for new assets; implementation-specific neutral surfaces may support it. Keep screenshot framing consistent with the real product rather than recoloring UI inside a marketing image.

Typography should be clear, compact and familiar. The extension uses a system sans-serif stack. Use deliberate size and weight hierarchy, short labels and comfortable spacing. Avoid dense all-caps marketing blocks, excessive gradients, ornamental badges or technical decoration.

## Daily usefulness and retention

The recurring loop is: choose Today or Yesterday, click Preview, reopen a useful page, and return later through a saved view. A weekly or project export is an optional outcome of that same loop. There is no need to export every day for the product to be useful.

Use the actual control names in walkthroughs:

- **Today's recap / Yesterday's recap:** visits, pages and sites in the loaded date range.
- **Most visited sites:** the top three sites by visit count, clickable to filter the trail.
- **Your recent trail:** newest-first matching pages, with safe web links that reopen in a tab.
- **Save view / Your saved views:** named local range, filter and export settings. Selecting a saved view restores the settings; Preview or export reads current history.
- **Refresh:** reads the history again to include new visits.

Retention is a hypothesis to measure through voluntary feedback and aggregate store trends. Do not claim the recap has already improved retention. Keep history reads user-initiated and do not add streaks, surprise notifications or background tracking to create artificial engagement.

## Browser-neutral product, intentional search language

Use **browser history** in the brand, hero, interface and general product descriptions. Chrome, Edge and Brave are initial Chromium targets. Public browser support claims must follow the dated compatibility evidence, not just the presence of a browser logo.

It is appropriate to use **export Chrome history**, **Chrome history to CSV**, or **Better History alternative** in a relevant guide, comparison or search-focused tutorial. These phrases answer real queries and describe the current distribution context. Do not repeat them across the general brand or multiply thin pages by substituting a browser name.

The Chrome Web Store name should appear when it identifies the actual download destination. Do not show an Edge Add-ons badge unless there is a real published listing. Do not imply Firefox, Safari, mobile or universal browser support from the Chromium build.

## Copy boundaries

Say “all available history,” “latest matching visit,” “local settings,” “preview matching rows” and “CSV for spreadsheets.” Explain that a saved view is settings, not an immutable archive. URL cleanup removes query strings and fragments; it does not anonymize titles or paths.

Avoid “unlimited history,” “recover deleted history,” “native Excel workbook,” “complete work log,” “time tracker,” “anonymous export,” “works everywhere” and unverified superiority over competitors.

**Do not use em dashes, including the U+2014 character, anywhere in product copy, documentation or launch assets.** Use a period, colon, comma or ordinary hyphen when punctuation is needed. Keep the voice direct, useful and calm.

## Asset consistency

All screenshots must show the real v2 interface using synthetic public browsing data. All logo, icon, promotional and thumbnail assets must use the new identity. Capture the actual output file when showing export results. Save editable sources and raw UI captures so later releases can refresh the assets without reconstructing the product visually.

Brand completion does not establish release completion. Label an unreleased build a release candidate, and distinguish a real recorded demonstration from a script or animated preview.
